# 要件定義書: 設定パネル・関連ツールの UI ポリッシュ

## はじめに

`settings-panel-readonly` Spec により設定パネルのカテゴリタブ・アラームタブは閲覧専用に整理された。
本 Spec では、その後に判明した細かい UX 上の問題点を一括して修正する。
対象は以下の 4 つのエリアに分かれる。

1. **設定パネル → カテゴリタブ** — 閲覧専用カテゴリリストのビジュアル改善
2. **設定パネル → アラームタブ** — 閲覧専用アラームリストのビジュアル改善
3. **アラーム・エディタ** — 開いた直後の初期選択状態の改善
4. **アニメーション・メーカー** — GIF ドロップエリアの文言・シンボル修正

---

## 横断的制約: ライト / ダークモード両対応

**本 Spec の全要件・全変更は、ライトモードとダークモードのいずれでも視認性を維持しなければならない。**

具体的なルール:

- **色の直接指定は原則禁止。** 固定カラーコードや CSS literal color（`#fff`・`#000`・`rgba(0,0,0,0.5)` 等）を新たに使用してはならない。代わりに M3 CSS 変数（`var(--md-sys-color-*)` や `var(--app-color-*)` など、プロジェクトで定義済みのセマンティックトークン）を使用する。
- **例外 — Retro 系スウォッチの頭文字色:** Retro LCD / CRT / Nixie のスウォッチ背景色はそれぞれ固定色（`#9bbc0f` / `#33ff33` / `#f50`）であり既存 CSS でも固定値が使われている。これらの背景に対するコントラスト確保のための文字色（例: LCD → `#0f380f`、CRT → `#030c04`、Nixie → `#1a0800`）に限り、固定値の使用を許容する。ただしその値は既存の Retro CSS で使われているものと統一する。
- **コントラスト比:** テキスト・シンボルと背景色の組み合わせは、ライト・ダーク両モードで WCAG AA（通常テキスト 4.5:1 以上、大きめテキスト・アイコン 3:1 以上）を満たすこと。
- **スウォッチ色:** `getColorCode()` が返す固定 HEX 値はカラーパレットの「カテゴリ色」を表すものであり、表示上の意味のある情報（テーマカラー）なので固定値のままでよい。スウォッチ以外の UI 要素でこの値を流用してはならない。

## 要件一覧

---

### 要件 1: カテゴリタブ — リストと「編集」ボタン間の仕切り線の除去

**概要:** カテゴリアイテムリスト (`#category-editor-list`) と「編集」ボタンエリアとの間に引かれている `border-bottom: 1px solid` の仕切り線を削除する。

**背景:** 現在、`#category-editor-list` の CSS に `border-bottom` が設定されており、視覚的にリストと下部ボタン群を分けている。閲覧専用化によりリストの下にはエディタ起動ボタンのみが残っており、この仕切りは不要なノイズとなっている。

**受け入れ条件:**
- `#category-editor-list` に適用されている `border-bottom` スタイルが削除されている
- リストとボタンの間に線が表示されない

---

### 要件 2: カテゴリタブ — 改ページアイテムの中央揃え

**概要:** 閲覧専用リスト内の「改ページ」アイテム (`.page-break-item`) のシンボルと文字列を、現在の左上寄せから縦横中央揃えに変更する。

**背景:** 現在 `.page-break-item` 内の `.page-break-label` は `display: flex; align-items: center` が適用されているが、アイテム自体が `flex-direction: column` または通常の block 配置のため、水平方向の中央揃えがされていない。

**受け入れ条件:**
- `.page-break-item` 内のシンボル (`insert_page_break`) と「改ページ」テキストが、アイテム幅の中央に表示される
- 縦方向も中央揃えになっている

---

### 要件 3: カテゴリタブ — カラースウォッチの拡大と Retro 頭文字表示

**概要:** 閲覧専用カテゴリリストのカラースウォッチ（丸いドット）を、内部にテキストが読める程度のサイズまで拡大する。Retro LCD / CRT / Nixie のいずれかが選択されている場合、スウォッチ内に頭文字（それぞれ `L` / `C` / `N`）を表示する。

**背景:** 現在のスウォッチは `width: 16px; height: 16px` と小さく、Retro LCD・CRT・Nixie の 3 種を視覚的に区別できない。文字を表示できる程度のサイズ（24〜28px 程度）に拡大し、Retro 系については頭文字を重ねることで識別性を確保する。

**受け入れ条件:**
- スウォッチが 24px 以上のサイズになっている
- Retro LCD 選択時: スウォッチ内に `L`、Retro CRT 選択時: `C`、Retro Nixie 選択時: `N` の文字が表示される
- Retro 系の文字は背景色に対して視認できるコントラストを持つ
- 通常カラー（non-Retro）ではスウォッチ内に文字は表示されない

---

### 要件 4: カテゴリタブ — 業務カテゴリ名のフォントサイズ拡大

**概要:** 閲覧専用カテゴリアイテム内の業務カテゴリ名 (`.category-readonly-name`) のフォントサイズを、現在の設定項目名（ラベル）と同程度の小さいサイズから、設定項目値（例:「標準」）と同程度の大きさに引き上げる。

**背景:** 現在 `.category-readonly-name` は行インラインで定義されたデフォルトフォントサイズか、CSS で明示的なサイズが設定されていない。設定項目名（`.setting-item label`：`0.75rem`）と視覚的に同等になってしまっており、業務カテゴリ名としての重要度が伝わりにくい。設定項目値と同程度の `0.9rem`〜`1rem` 程度が適切。

**受け入れ条件:**
- `.category-readonly-name` のフォントサイズが `0.9rem` 以上に設定されている
- 業務カテゴリ名が設定ラベルより明確に大きく表示される

---

### 要件 5: カテゴリタブ — タグ・アニメーション設定の項目名を M3 Symbol 1 文字に変更

**概要:** 閲覧専用カテゴリアイテム内の「タグ」行の項目名ラベルを `shell` または `tag` シンボル 1 文字に、「背景アニメーション設定（共通）」行の項目名ラベルを `motion_photos_auto` または `animation` シンボル 1 文字に置き換える。全言語共通とする。

**背景:** 現在、タグ行には `t('tags') + ': '` というテキストラベルが使用されている。多言語対応で各言語のラベル幅が異なり、レイアウトが崩れる原因となっている。Material Symbols を使った視覚的なアイコン 1 文字であれば全言語でサイズが安定し、スペースも節約できる。

**シンボル選択:**
- タグ行: `sell` (M3 で「タグ・ラベル」に最も近い形状)
- アニメーション設定行: `animation` (M3 Animation シンボル)

**受け入れ条件:**
- タグ行の項目名が `material-symbols-outlined` クラスの `span` でシンボルテキスト `sell` を表示している
- アニメーション設定行の項目名が `material-symbols-outlined` クラスの `span` でシンボルテキスト `animation` を表示している
- テキストラベルおよび `data-i18n` 属性は当該ラベル `span` から除去されている（シンボルは翻訳不要）

---

### 要件 6: カテゴリタブ — 業務カテゴリ名・タグ・アニメーション設定の左揃えレイアウト統一

**概要:** 閲覧専用カテゴリアイテム内の業務カテゴリ名（row-1）、タグ行（row-2）、アニメーション設定行（row-3）の 3 行を独立した行として縦に積み、カラースウォッチの右端から適切な間隔をあけた位置に左端をそろえてレイアウトする。

**背景:** 現在、row-1（スウォッチ + 名前）と row-2（タグ + アニメーションをまとめた `flex-direction: column` の div）は別々の `div` で縦に積まれており、row-2 はスウォッチ幅を考慮していないため左端がそろっていない。タグとアニメーション設定は row-2 / row-3 として独立した行に分け、スウォッチ右端＋ gap（8px 程度）の位置を共通の左辺基準として、3 行すべての左端が縦に面をそろえて見えるようにする。

**受け入れ条件:**
- row-1（業務カテゴリ名）・row-2（タグシンボル+値）・row-3（アニメーションシンボル+値）の 3 行がそれぞれ独立した div 要素として生成される
- 3 行の左端が、カラースウォッチの右端＋ gap（8px 程度）の位置に揃っている
- カラースウォッチと重なっていない（最低 8px の間隔がある）

---

### 要件 7: カテゴリタブ — タグ未設定時のシンボル表示維持

**概要:** タグが 1 つも設定されていない業務カテゴリの閲覧専用アイテムでも、タグ行の `sell` シンボルのみは常に表示する。シンボルの右側に値テキストは表示しない（空欄のまま）。

**背景:** 現在タグが空の場合はタグ行自体が生成されないため、カテゴリによってアイテムの高さが変動する。シンボルのみを常に表示することで高さを統一し、一覧のスキャン性が向上する。（改ページアイテムは例外）

**受け入れ条件:**
- タグ未設定のカテゴリアイテムでも `sell` シンボルを含むタグ行が表示される
- タグが設定されている場合はシンボルの右にタグ値が表示される
- 改ページアイテムはこのルールの対象外

---

### 要件 8: カテゴリタブ — アニメーション未設定時の「無し」表示

**概要:** 背景アニメーションが設定されていない（または `none`）業務カテゴリの閲覧専用アイテムでも、アニメーション設定行を表示し、値として「無し」（`t('anim-none')` で取得）を表示する。

**背景:** 現在アニメーションが `none` の場合はアニメーション設定行自体が生成されないため、アイテムの高さが変動する。常に表示することで高さを統一する。（改ページアイテムは例外）

**受け入れ条件:**
- アニメーション未設定（`none` または未指定）のカテゴリでも `animation` シンボルを含むアニメーション設定行が表示される
- 値テキストとして `t('anim-none')` の翻訳文字列が表示される
- アニメーションが設定されている場合は既存通りアニメーション名が表示される
- 改ページアイテムはこのルールの対象外

---

### 要件 9: カテゴリタブ — 各テキスト値の末尾省略

**概要:** 閲覧専用カテゴリアイテム内の業務カテゴリ名・タグ値・アニメーション設定値が、アイテム幅を超える場合に `text-overflow: ellipsis` で末尾省略し、改行を発生させない。

**背景:** 長い名前やタグ文字列がアイテムを縦に押し広げ、一覧の高さが不均一になる。省略表示により各アイテムの高さが統一される。（改ページアイテムは例外）

**受け入れ条件:**
- 業務カテゴリ名・タグ値・アニメーション名に `overflow: hidden; white-space: nowrap; text-overflow: ellipsis` が適用されている
- テキストがアイテム幅を超えた場合に `...` で省略表示される
- 折り返し（改行）は発生しない

---

### 要件 10: アラームタブ — 稼働曜日チップの Disabled スタイル解除

**概要:** 設定パネルのアラームタブに表示される「稼働曜日」の `.filter-chip[disabled]` に適用される灰色フィルター（`opacity` による減色）を解除し、`enabled` と同じ見た目にする。編集不可の動作は維持する。

**背景:** 現在 `disabled` 属性が付いたボタン要素はブラウザのデフォルトまたは CSS の `button:disabled { opacity: 0.5 }` により薄くなる。稼働曜日は編集不可だが「閲覧専用の情報表示」なので、内容が明確に読める状態にすべき。アラームエディタの稼働曜日チップ（編集可能）は影響を受けてはならない。

**受け入れ条件:**
- `#business-days-container` 内の `.filter-chip` は `disabled` 状態でも通常と同じ色・不透明度で表示される
- 日曜日は `--app-color-sunday`、土曜日は `--app-color-saturday` で、活性・不活性状態ともに色が正しく表示される
- チップをクリックしても値が変更されない（`disabled` 属性は保持）

---

### 要件 11: アラームタブ — 「稼働曜日」編集ボタンの横幅縮小

**概要:** 稼働曜日チップの右横に配置されている「編集」ボタン (`#business-days-edit-btn`) の横幅を、シンボルアイコン（鉛筆）のサイズにフィットする最小限の幅に縮小する。

**背景:** 現在 `icon-btn` クラスには `width: 36px; height: 36px` が設定されており、これが意図通りに機能していれば問題ないはずだが、`renderBusinessDays()` で `marginLeft: '8px'` の inline style が付いており、実際には横幅が過剰に見えるケースがある。アイコンボタンとして一貫した正方形 36×36px に収まるようにする。

**受け入れ条件:**
- `#business-days-edit-btn` の表示上の横幅が不必要に広くなっていない（36px 程度）
- ボタンの横幅がアイコン（鉛筆シンボル）のサイズに対して適切

---

### 要件 12: アラームタブ — 時刻フィールドの横幅最適化と「確認が必要」の右寄せ

**概要:** 各アラームアイテムの時刻表示 (`.alarm-time`) が不必要に横長にならないようにする。具体的には `flex: 1` による伸長を廃止し、コンテンツ幅（時刻テキスト）に合った必要十分な幅に縮小する。「確認が必要」のフィードバック要素 (`.alarm-confirm`) は時刻フィールドが縮小しても同行の右端に表示されるよう `margin-left: auto` を適用する。

**背景:** 現在の `.alarm-time { flex: 1 }` により時刻テキストが横一杯に伸びており、視覚的に不均衡。時刻は固定幅コンテンツであるため、幅を内容に合わせる（`flex: none` または `width: fit-content`）。

**受け入れ条件:**
- `.alarm-time` の幅がテキスト内容（例: `09:00`）に必要な幅に収まっている
- `.alarm-confirm` が常に行の右端に表示される（`margin-left: auto` 相当）
- 時刻フィールドが縮まっても「確認が必要」は同一行に右寄せで維持される

### 要件 13: アラーム・エディタ — 初期起動時に先頭アラームを選択済み状態にする

**概要:** アラーム・エディタ (`projects/alarm-editor/`) を開いた直後、アラームリストの先頭アイテムが選択状態になり、右側ペインにその詳細が表示されるようにする。

**背景:** 現在 `alarm-editor.js` の `init()` では `state.selectedAlarmId = null` のまま `ui.renderDetail()` を呼ぶため、起動直後は右ペインに「左側からアラームを選択してください。」という空の状態が表示される。先頭アイテムを自動選択することで、すぐに内容を確認・編集できる。

**受け入れ条件:**
- `init()` 完了後に `state.alarms` の先頭要素（インデックス 0）の `id` が `state.selectedAlarmId` に設定されている
- 起動直後から右ペインに先頭アラームの詳細が表示されている
- アラームが 0 件の場合は従来通り空状態（`alarm-editor-select-prompt`）を表示する

---

### 要件 14: アニメーション・メーカー — GIF ドロップゾーンの文言とシンボルの変更

**概要:** アニメーション・メーカーの設定セクション内 GIF ドロップゾーン (`#drop-zone`) の文言とシンボルを以下のとおり変更する。

**文言変更:**
- 変更前: `「ここにGIFファイルをドラッグ＆ドロップするか、クリックして選択してください」`（i18n キー `maker-drop-hint`、全言語）
- 変更後: `「ここにアニメーションGIFをドロップするか、クリックして選択してください」`

**シンボル変更:**
- 変更前: `cloud_upload`（inline style で `#drop-zone` 内に記述）
- 変更後: `gif_box`

**受け入れ条件:**
- `maker-drop-hint` の全言語翻訳が新しい文言に更新されている（各言語で意味を維持した翻訳）
- `#drop-zone` 内のシンボル `span` が `gif_box` を表示している
- 機能（ファイル選択・ドラッグ&ドロップ）は変更なし
