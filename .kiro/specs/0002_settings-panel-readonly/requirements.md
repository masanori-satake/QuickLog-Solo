# 要件定義書: 設定パネルの閲覧専用化とエディタ連携強化

## はじめに

QuickLog-Solo の「設定」パネルは、これまでパネル内でのインライン編集と、外部エディタ（業務カテゴリ・エディタ、アラーム・エディタ）による編集を併用する構成だった。
設定項目の増加に伴い、パネル内編集とエディタ編集の二重管理が複雑さを増し、両者の間で設定値が食い違うリスクも生じていた。

本 spec では次の方針を適用する。

- **「設定」パネルのカテゴリタブ・アラームタブは原則として閲覧専用とする。**
- **編集はそれぞれのエディタ（業務カテゴリ・エディタ / アラーム・エディタ）でのみ行う。**
- 例外として、アラームタブの各エントリーの「有効」チェックボックスのみパネル内でトグル可能とする。
- 同様に、アラームタブの「稼働曜日」はパネル内のチップで直接変更するのではなく、鉛筆ボタン経由でアラーム・エディタを起動して編集する。
- エディタで「適用」を実行した際、設定パネルの該当タブに即時反映される。タブの切り替えや設定パネルの再表示は不要。
- エディタと設定パネル間でクリップボードを経由していたデータ受け渡し機能（「カテゴリの入出力 (クリップボード)」「アラームの入出力 (クリップボード)」）は不要となったため削除する。
- 削除した UI 要素が占めていた領域はリスト表示領域に充て、一覧性を向上させる。

---

## 用語集

| 用語 | 定義 |
|------|------|
| **設定パネル** | `#settings-popup` 内の設定 UI 全体。タブ切り替え式 |
| **カテゴリタブ** | `#categories-tab`。カテゴリ一覧の確認とエディタ起動を担う |
| **アラームタブ** | `#alarms-tab`。アラーム一覧の確認と有効トグル、エディタ起動を担う |
| **業務カテゴリ・エディタ** | `projects/category-editor/` で定義された別タブのエディタ |
| **アラーム・エディタ** | `projects/alarm-editor/` で定義された別タブのエディタ |
| **BroadcastChannel** | `quicklog_solo_sync_QuickLogSoloDB` チャンネル。エディタ→メインアプリへの変更通知に使用 |
| **閲覧専用エントリー** | 値を表示するが、ユーザーが直接変更できない UI 要素 |
| **「編集」ボタン** | これまで「業務カテゴリ・エディタを起動」「アラーム・エディタを起動」だったボタンの新ラベル |

## 要件一覧

---

### 要件 1: カテゴリタブの閲覧専用化

**ユーザーストーリー:** 設定パネルのカテゴリタブでカテゴリ一覧を確認する際、誤操作でカテゴリ名・色・アニメーション・タグを変更してしまわないようにしたい。編集は業務カテゴリ・エディタで行う。

#### 受け入れ基準

1. カテゴリタブのカテゴリ一覧（`#category-editor-list`）に表示される各エントリーは、値の表示のみを行うテキスト要素（`textContent`）に切り替わっており、`<input>`・`<select>`・カラードロップダウン・タグ入力などの編集可能な要素を含まない。
2. ドラッグ＆ドロップによる並び替えハンドル（`drag_indicator` アイコン）は非表示または無効化されており、ドラッグ操作は受け付けない。
3. 各エントリーの削除ボタン（`delete-cat-btn`）は非表示または無効化されており、パネル内からカテゴリを削除できない。
4. 改ページ（`SYSTEM_CATEGORY_PAGE_BREAK`）エントリーも同様に閲覧専用の表示となる。
5. 各カテゴリエントリーには、カテゴリ名・カテゴリカラー（色見本）・タグ（設定されている場合）・アニメーション名（設定されている場合）を表示する。改ページエントリーはアイコンと「改ページ」ラベルを表示する。
6. 閲覧専用エントリーは、ユーザーが編集可能と誤認しないよう視覚的に区別する。具体的には以下のいずれかまたは複数の手法を組み合わせること。
   - 入力フォーム要素（`<input>`・`<select>`等）を使わず、プレーンなテキスト要素で表示する。
   - エントリー全体またはリストコンテナに `pointer-events: none` や `user-select: none` は使用しない（有効チェックボックス等の操作可能要素と共存させるため）。ただし個々のテキスト表示要素には `cursor: default` を適用し、クリック可能に見せない。
   - エントリーの背景色を通常の編集リストアイテムと区別できる色調（`--md-sys-color-surface-variant` など）にするか、左端に読み取り専用を示すインジケーター（細い縦線など）を設ける。
   - ホバー時に編集用のハイライト（フォーカスリング等）が表示されない。

### 要件 2: カテゴリタブの不要 UI 要素の削除

**ユーザーストーリー:** カテゴリタブでクリップボード経由のインポート・エクスポートや、パネル内でのカテゴリ追加・改ページ追加を行う必要がなくなったため、これらの UI 要素を削除してその領域を有効活用したい。

#### 受け入れ基準

1. 「新しいカテゴリ...」テキスト入力と「カテゴリを追加」ボタン（`#add-category-box-settings` 全体）が DOM から除去されている。
2. 「改ページを追加」ボタン（`add-page-break-btn`）が DOM から除去されている。
3. 「カテゴリの入出力 (クリップボード)」セクション（ラベル・「コピー (Export)」ボタン・「貼り付け (Import)」ボタン・インポートモード選択ラジオボタン）が DOM から除去されている。
4. これら要素の削除によって生まれた余白はカテゴリ一覧のスクロール領域として再利用され、以前より多くのカテゴリが一度に見渡せるようになっている（一覧性向上）。
5. 上記削除に対応する JavaScript イベントリスナー（`add-category-btn-settings`・`add-page-break-btn`・`export-categories-btn`・`import-categories-btn`）も `app.js` から除去されている。
6. `renderCategoryEditor()` 関数は新しい閲覧専用 UI を描画する関数（例：`renderCategoryList()`）に置き換えるか、内部実装を完全に書き換える。旧実装のコードブロック（`nameInput` 生成・`colorDropdown` 生成・`animSelect` 生成・`tagInput` 生成・ドラッグイベント登録・削除ボタン生成など）は一行も残さない。
7. 削除後も、現在の i18n キーのうち他箇所で使用されているものは削除しない（`category-backup`・`btn-export-json`・`btn-import-json`・`import-append`・`import-overwrite` 等は他コンポーネントやエディタで使用されている可能性があるため影響範囲を確認すること）。

### 要件 3: カテゴリタブの「編集」ボタン

**ユーザーストーリー:** 業務カテゴリ・エディタを起動するボタンのラベルが「業務カテゴリ・エディタを起動」から「編集」に変わることで、ボタンの役割が直感的に分かるようにしたい。

#### 受け入れ基準

1. カテゴリタブ内の業務カテゴリ・エディタ起動ボタン（`advanced-editor-link`）のラベルが「編集」に変更されている。
2. `btn-launch-category-editor` キーが以下の翻訳値に更新されている（全言語ファイルに適用すること）。

   | 言語ファイル | 更新後の値 |
   |------------|-----------|
   | `ja.js` | `編集` |
   | `en.js` | `Edit` |
   | `de.js` | `Bearbeiten` |
   | `es.js` | `Editar` |
   | `fr.js` | `Modifier` |
   | `pt.js` | `Editar` |
   | `ko.js` | `편집` |
   | `zh.js` | `编辑` |

3. ボタンのアイコン（`edit_note`）は変更しなくてよい。ただし、アイコンとラベルの組み合わせが「編集」という意図を明示できていること。
4. ボタンのクリックで業務カテゴリ・エディタが新タブで起動する動作は従来通り維持されている。

### 要件 4: アラームタブの閲覧専用化（有効チェックボックスを除く）

**ユーザーストーリー:** アラームタブでアラーム設定の概要を確認する際、有効/無効の切り替え以外の設定（時刻・タイプ・アクション等）を誤って変更してしまわないようにしたい。

#### 受け入れ基準

1. アラームタブの各アラームエントリーにおいて、「有効」チェックボックス（`alarm-enabled`）のみが引き続き変更可能な `<input type="checkbox">` として残る。
2. 時刻（`alarm-time`）・確認チェックボックス（`alarm-confirm`）・実行タイミング選択（`alarm-type`）・曜日選択（`alarm-daysOfWeek`）・日付入力（`alarm-day-of-month`）・月末起算入力（`alarm-days-before-end`）・非稼働日調整選択（`alarm-holiday-adj`）・メッセージ入力（`alarm-message`）・動作選択（`alarm-action`）・開始カテゴリ選択（`alarm-category`）は、すべて閲覧専用の表示要素（`textContent`）に置き換わっており、ユーザーが直接値を変更できない。
3. 有効チェックボックスを変更すると、即座に IndexedDB に保存され（`dbPut(STORE_ALARMS, alarm)`）、`broadcastSync('alarms-updated')` が呼ばれる。
4. 確認チェックボックス（`alarm-confirm`）も同様に閲覧専用とし、パネルには現在の状態をアイコンやテキストで表示する。
5. 閲覧専用の表示項目は、ユーザーが編集可能と誤認しないよう視覚的に区別する。具体的には以下のいずれかまたは複数の手法を組み合わせること。
   - `<input>`・`<select>` を使わず、プレーンなテキスト要素（`<span>`・`<p>` 等）で値を表示する。
   - 各テキスト表示要素には `cursor: default` を適用し、クリック可能に見せない。
   - フォーム要素を模したスタイル（border・background 等）をテキスト要素に付けず、ラベルと値のペアとして読みやすいレイアウトで表示する。
   - ホバー時に編集用ハイライトやフォーカスリングが表示されない。

---

### 要件 5: アラームタブの不要 UI 要素の削除

**ユーザーストーリー:** アラームタブでクリップボード経由のインポート・エクスポートを行う必要がなくなったため、これらの UI 要素を削除してその領域を有効活用したい。

#### 受け入れ基準

1. 「アラームの入出力 (クリップボード)」セクション（ラベル・「コピー (Export)」ボタン `export-alarms-btn`・「貼り付け (Import)」ボタン `import-alarms-btn`）が DOM から除去されている。
2. これら要素の削除によって生まれた余白はアラーム一覧のスクロール領域として再利用され、以前より多くのアラームが一度に見渡せるようになっている（一覧性向上）。
3. 上記削除に対応する JavaScript イベントリスナー（`export-alarms-btn`・`import-alarms-btn`）も `app.js` から除去されている。
4. `renderAlarmList()` 内の `updateAlarm()` 関数（および各フォーム要素への `onchange` 登録）は、有効チェックボックス（`enabledCheck`）の処理のみ残し、他のフォーム要素に対応するコードはすべて除去する。不要になった変数定義（`timeInput`・`confirmCheck`・`typeSelect` 等の `createEl` 呼び出し）も含めて残さない。
5. 「アラーム・エディタを起動」ボタン（`alarm-editor-link`）は「編集」ボタンとして残る（要件 6 参照）。

### 要件 6: アラームタブの「編集」ボタンとレイアウト

#### 受け入れ基準

1. アラームタブ内のアラーム・エディタ起動ボタン（`alarm-editor-link`）のラベルが「編集」に変更されている。
2. `btn-launch-alarm-editor` キーが以下の翻訳値に更新されている（全言語ファイルに適用すること）。

   | 言語ファイル | 更新後の値 |
   |------------|-----------|
   | `ja.js` | `編集` |
   | `en.js` | `Edit` |
   | `de.js` | `Bearbeiten` |
   | `es.js` | `Editar` |
   | `fr.js` | `Modifier` |
   | `pt.js` | `Editar` |
   | `ko.js` | `편집` |
   | `zh.js` | `编辑` |

3. ボタンのアイコン（`edit_notifications`）は変更しなくてよい。
4. 「編集」ボタンと「通知のテストを実行する」ボタン（`test-notification-btn`）の間に視覚的な仕切り線（`<hr>` または CSS border による `divider`）が追加されている。
5. ボタンのクリックでアラーム・エディタが新タブで起動する動作は従来通り維持されている。

### 要件 7: 稼働曜日の閲覧専用化と鉛筆ボタンによる編集起動

**ユーザーストーリー:** アラームタブの「稼働曜日」でチップを直接クリックして変更するのではなく、アラーム・エディタ経由でのみ変更できるようにしたい。チップ群の右隣に鉛筆ボタンを設け、それを押してエディタを起動できるようにしたい。

#### 受け入れ基準

1. 「稼働曜日」の各曜日チップ（`filter-chip`）は、クリックしても稼働曜日の変更が発生しない（`onclick` ハンドラが除去または無効化されている）。
2. チップのスタイルとして、アクティブ（稼働日）・非アクティブ（非稼働日）の視覚的区別（現在の `.active` クラスによる色分け）は閲覧専用でも維持される。
3. 曜日チップ群（`#business-days-container`）の右隣に鉛筆アイコン（`edit` または `edit_note`）のボタンが配置されている。
4. 鉛筆ボタンをクリックすると、アラーム・エディタが新タブで起動する（`alarm-editor-link` と同じ `getLaunchProjectUrl` ロジックを使用）。
5. 鉛筆ボタンには適切な `title` 属性（ツールチップ）が設定されており、i18n 対応している。

### 要件 8: エディタでの変更を設定パネルに即時反映

**ユーザーストーリー:** 業務カテゴリ・エディタまたはアラーム・エディタで「適用」を実行した際、設定パネルを再表示したりタブを切り替えたりしなくても、該当タブの表示が即座に更新されてほしい。

#### 受け入れ基準

1. 業務カテゴリ・エディタが BroadcastChannel で `{ type: 'sync' }` を送信した際、設定パネルが開いていてカテゴリタブが表示中であれば、`renderCategoryList()` 相当の再描画が自動的に実行される。
2. アラーム・エディタが BroadcastChannel で `{ type: 'alarms-updated' }` を送信した際、設定パネルが開いていてアラームタブが表示中であれば、`renderAlarmList()` および `renderBusinessDays()` の再描画が自動的に実行される。
3. 設定パネルが閉じている場合、または対象タブが表示されていない場合は、パネルを次に開く・タブに切り替える際に最新データで描画されれば十分（強制再描画は不要）。
4. 再描画はユーザーが操作中の UI 要素（フォーカス中の有効チェックボックス等）を強制的に上書きしない（既存の `document.activeElement` ガード相当の保護を維持する）。

### 要件 9: i18n 更新（全言語対応）

**ユーザーストーリー:** 「編集」ボタンや鉛筆ボタンの新しいラベル・ツールチップが、サポートする全 8 言語（en / ja / de / es / fr / pt / ko / zh）で適切に翻訳されていてほしい。

#### 受け入れ基準

1. `btn-launch-category-editor` キーが全言語ファイルで要件 3 の翻訳表に従った文字列に更新されている。
2. `btn-launch-alarm-editor` キーが全言語ファイルで要件 6 の翻訳表に従った文字列に更新されている。
3. 稼働曜日の鉛筆ボタン用ツールチップキー（例：`tooltip-edit-business-days`）が全言語ファイルに追加されている。各言語の値の目安は以下の通り。

### 要件 10: テストと動作検証

**ユーザーストーリー:** 本 spec の変更後も、既存のユニットテストおよび E2E テストが引き続きパスし、変更対象の機能が意図通りに動作することを確認したい。

#### 受け入れ基準

1. `npm test`（Jest ユニットテスト）が全テストパスする。
2. 既存の Playwright E2E テスト（`tests/*.spec.js`）で、カテゴリタブ・アラームタブに関連するテストが変更後も引き続きパスする（または変更内容に合わせて適切に更新されている）。
3. アラームタブで有効チェックボックスをトグルすると、再描画後もチェック状態が正しく反映される（DB 保存 → BroadcastChannel → 再描画の疎通確認）。
4. 業務カテゴリ・エディタで変更を適用した後、設定パネルのカテゴリタブを開いている場合に一覧が即時更新されることを手動または自動テストで確認する。
5. アラーム・エディタで変更を適用した後、設定パネルのアラームタブを開いている場合に一覧が即時更新されることを手動または自動テストで確認する。

## 非機能要件

- **デッドコード禁止:** 閲覧専用化によって不要になったコードは、コメントアウト・`disabled` 属性付き残置・使用されない変数定義のいずれの形でも残してはならない。削除対象の具体的な範囲は各要件の受け入れ基準に記載する。変更後に ESLint の `no-unused-vars` が新たな警告を出さないことで確認する。
- **セキュリティ:** 閲覧専用 UI に切り替えた後も、`textContent` によるテキスト表示を使用し `innerHTML` は使用しない（既存のセキュリティポリシーを維持）。
- **パフォーマンス:** 閲覧専用の再描画は、既存の `renderCategoryEditor()` / `renderAlarmList()` の再描画コストを超えない。
- **アクセシビリティ:** 閲覧専用テキスト要素には `aria-readonly="true"` を付与することを推奨するが必須ではない。
- **バージョンバンプ:** `projects/app/` および `shared/` への変更を伴うため、`npm run version:bump` によるマイナーバージョンバンプが必要（機能変更のため）。
